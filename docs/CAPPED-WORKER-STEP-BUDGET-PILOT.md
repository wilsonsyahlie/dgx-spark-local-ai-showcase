# A capped pilot of additional worker steps

The pilot did not demonstrate a completion gain that justified expanding the experiment.

| Measure | Eight steps | Twelve steps |
| --- | ---: | ---: |
| Jobs observed | 3 | 3 |
| Clean completions | 0 | 2 |
| Entire frozen suite passed | 3 | 2 |
| Verified case credits | 47 | 31 |
| Accepted requests | 21 | 21 |
| Defined tool failures | 2 | 2 |
| Worker seconds | 219.09 | 225.80 |

The experiment used three fresh, distinct standalone module contracts, with one new job per arm and no retries, coaching, old-output continuation or replacement tasks. Within each pair, task instructions, independently qualified hidden cases, model, output allowance, sampling and tool authority matched. Only the execution ceiling and its mechanically consistent advertised wording changed from eight to twelve. Alternating first arm across three pairs produces a two-to-one imbalance, which is disclosed rather than described as exact balance.

Before inference, the contracts, source copies, graders, metrics and decision rule were frozen. A clean completion required returned status, all frozen cases passing and positive ownership settlement; correct saved work with an exhausted budget remained incomplete. The preliminary gate required at least one additional clean completion and zero previously passing case regressions. A positive signal would support proposing a larger trial only. Neither production adoption nor a subsequent experiment was authorized.

The pilot was capped at six one-shot jobs and sixty accepted requests. A cumulative fifteen-minute worker-time threshold requested cancellation of owned work, with polling and cleanup/settlement overrun possible. Per-request output/time limits and the per-job watchdog remained unchanged. The cap was a stop threshold, not a promise of an exact elapsed-time ceiling.

Sixteen real independent correct-reference, targeted-broken, missing-export and wrong-export-shape controls qualified forty-seven shared cases per arm. Deterministic worker controls exercised the eight/twelve ceilings, finishing after steps nine and twelve, refusal of a thirteenth request, Stop, unresolved ownership and tool-call bounds. Actual request construction matched apart from the required maximum-step numeral. An actual aggregate-watchdog control stopped its owned synthetic worker while preserving a correct artifact as incomplete. Existing harness controls covered durable exclusive intents, crash/pause recovery, hidden-reference isolation, checker infrastructure faults and no replay. Privacy and independent-review gates were separately qualified.

Preparation retained two corrections: a receipt reader initially assumed a different success-field schema, and shell redirection created task source files before the program's private umask took effect. The reader was corrected against the actual qualified schema; private source modes were corrected with preceding byte/stat backups and unchanged hashes. No acceptance assertion was relaxed. The prevention lesson is to validate a producer's documented receipt shape and set the shell umask before creating its input file.

The audit verified 42 accepted native requests and 39 main-lane executor settlements. The executor denominator includes sixteen prelaunch qualification checks plus worker and final grading checks; it is not a worker-only count. All owned workers and graders settled,watchdogs closed,and the isolated lane was idle. Production sources,controller,state,resident runtime,historical evidence and existing dirty checkouts were preserved. 1 twelve-step jobs actually used steps beyond eight; 16 previously passing cases regressed and 0 cases improved.

This is a small selected module workload with one sample per arm, bounded cases and a first-arm imbalance. It cannot establish statistical significance, broad coding capability, throughput, model learning or application-level gain. Own-check success and worker report truthfulness remain separate from independent artifact acceptance. Early output-limit or incomplete failures stay in the denominator and are not evidence of intrinsic task difficulty. No production activation, ordinary supervised application dispatch, physical phone control or scheduled delivery was tested. Increasing a finish allowance cannot by itself establish that the model generates better code. The production limit was preserved; any larger trial or deployment needs its own authorized scope.

The result is mixed: defined clean completion improved by two jobs, but sixteen previously passing cases regressed, failing the frozen zero-regression rule. One twelve-step job returned on its tenth request; steps nine and ten supplied a file read and final report; cleanup was attempted at step eight, with no later implementation change. No coding-quality increase was established. Both patching implementations also reject function-valued extra fields outside the sealed cases; their source and own-check expectations expose that coverage limit. No supplementary runtime probe, repair or rescore was performed. One own rejection helper caught its own failure sentinel; the other enforced that sentinel but still used a wrong extra-field expectation. Printed checks and thirty reported passes were kept separate from independent acceptance.

Independent final review corrected an action-order narrative using indexed response outputs. Cleanup occurred within the original allowance; the extra requests read a file and returned the report. Non-action records may precede tool calls, so action attribution must bind the actual request index and item type. Raw results remained unchanged and the first unpublished review trees were retained.
