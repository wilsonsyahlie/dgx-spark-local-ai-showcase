# A matched test of file-based worker self-check instructions

The candidate did not meet the predeclared gates. The experiment provides no basis for adoption or a capability-gain claim.

Ten new standalone coding contracts were run once under each arm, for twenty fresh local jobs. Contracts, initial specifications, independently qualified hidden cases, model, sampling, tools and budgets matched within each pair. The first arm alternated across pairs. The candidate added instructions to save and execute substantive self-checks with short argument arrays, retain verification files, and finish with a truthful report. Only the worker system instruction changed. No coaching, retries, cross-arm feedback, previous-job replay, second candidate or production adoption occurred.

A clean completion required a returned worker, all frozen cases passing, and independently proven execution settlement. Correct saved code with an exhausted budget remained incomplete. The recommendation gate required at least two additional clean completions, strictly fewer narrowly defined tool failures, and zero baseline-pass/candidate-fail cases. These rules were frozen before any inference. Tool failures meant malformed check arguments and failed shell removal attempts with explicit read-only errors; failed substantive assertions were not automatically counted as waste.

Before launch, an independent review rejected false acceptance caused by JSON normalization conflating distinct JavaScript values, reused tool-call identifiers collapsing separate occurrences, and callable records passing object-only contracts. The corrected grader preserves null, nonfinite values, undefined, array holes and own keys; metrics count actual occurrences and hold ambiguous reconciliation. Trusted expression syntax is compiled before student initialization, so checker syntax errors cannot earn expected-rejection credit. Five record-type controls closed the measured domain gaps without relaxing either arm's contract.

Forty-eight actual correct-reference and targeted-broken controls, ten structural-value controls, three causal syntax controls, thirteen harness scenarios, six runtime-drift controls, request-equality controls, and publication privacy/review controls passed before launch. Earlier failed fixtures and the rejected first freeze remain retained. A producer/consumer ordering mistake also recurred: separate fixture directories did not eliminate shared lifecycle dependencies. Completion, validated output and settlement barriers replaced premature consumer execution while retaining the original guards. An identical fixture rewrite was rejected before mutation and then avoided by verifying unchanged bytes. Private task-source permissions were corrected with preceding backups. Historical missing-backup timing failures remain disclosed; later recovery does not retroactively establish a preceding copy.

All twenty one-shot jobs, their available saved implementations, any missing artifacts, and identical 138 cases per arm were audited from frozen-source-bound receipts. 116 accepted inference requests and 50 worker/grader executions had fresh settlement proofs; watchdogs closed and the isolated lane was idle. Repeated failure signatures paused dispatch for independent review; only remaining fresh labels continued, with no replay or instruction adjustment. The first two candidate jobs illustrate the finish problem: both artifacts passed all hidden cases, but extra own-check corrections or rechecks used the last available step. An unexecuted corrected self-check was not reported as passed. Several baseline self-check files also caught their own missing-throw sentinel, so their success output did not establish rejection coverage. An actual reserved-name map failure was observed and corrected by one baseline worker before its independent grade. A candidate preferences checker wrongly rejected numeric 2.0 and required shared array identity despite a fresh-copy contract. Terminal diagnostics recorded incomplete responses at the fixed output cap; the reason generation reached that limit and raw token provenance remain unproven. These findings remain separate from the frozen scores.

This is one instruction candidate, ten small-module pairs and one sample per arm. The new workload cannot be compared directly with the earlier descriptive pilot or application experiments. It is not a broad capability benchmark, weight-learning result or throughput qualification. Independently accepted frozen cases do not prove every possible behavior. Ordinary supervised application dispatch, physical phone controls, scheduled delivery and production activation were not exercised. Existing runtime, production sources/controller/state, prior experiment artifacts and dirty working trees were preserved. Immediate backups, rollback boundaries, mounted operating-knowledge readback and independent reviews support this experimental record; they do not turn a negative result into an improvement.
