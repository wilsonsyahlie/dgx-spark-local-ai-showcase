# A memory correction that did not become a retained upgrade

A local assistant sometimes omitted memory that was already ready while it prepared an answer. A deterministic experiment reproduced the publication boundary with invented context. A narrow correction reconsidered ready context after existing work, retaining the original cache and external-call sequence.

The candidate passed 108 focused software checks and seven packaged cases. It was installed in a bounded trial, and seven checks using code copied from that running artifact also passed in an isolated offline capsule. These checks demonstrate source behavior with invented inputs; they do not measure real-user memory accuracy or a general speed increase.

The one ordinary chat canary failed its response requirement, fixed before execution. Safe request completion and process cleanup were proved separately, but those facts did not turn the failed canary into a pass. The mismatch was not causally attributed to the correction.

The earlier software was recovered through a separately reviewed program-only reversal. Current saved data and the failed evidence were retained. An existing quiet scheduled job subsequently completed naturally, with a saved output, a future run and durable suppression showing zero send attempts. The candidate was not retained, and no performance gain was claimed.

The trial also sharpened interruption handling: an exited helper wrapper does not prove its children have closed. Each previously captured process needs an independent bounded wait, and repeated stop signals must defer through cleanup. Initial failed controls remained failures after corrected controls passed.

The engineering lesson is to keep software correctness, model-output acceptance and recovery safety distinct. A promising code fix can pass its own boundary checks without meeting a complete adoption rule. Future experiments need their own protocol set before execution; changing an assertion afterward would erase the value of the evidence.

This is a retrospective account, not deployment instructions. Physical device behavior, real-user memory accuracy and a broad speed or quality gain were not established.
