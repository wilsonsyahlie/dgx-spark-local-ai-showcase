# Turning generic worker failures into useful evidence

Several different local worker failures appeared as the same generic message. A controlled reproduction showed that terminal information was discarded. The correction preserved fixed short classifications and bounded structured fields while excluding arbitrary backend messages and request echoes from diagnostics.

Cleanup stayed authoritative. An identity mismatch could not redirect settlement, a diagnostic write fault could not suppress cancellation, and an earlier persistence fault remained visible after later successful work. Existing budgets and tool authority were retained; no retry or fallback was added.

A separate approved runtime qualification checked complete tool declarations across every supported effort level using isolated local capture without credentials or inference. A repeated teardown-test failure triggered independent review. Closing input and collecting evidence before tearing down isolation resolved the test boundary; the missing historical unit-name and command records stayed explicitly unproven.

Focused controls covered stream failures, malformed data, hostile fields, exact ownership and persistence faults. Integration checked actual journal and detail paths. Injected browser checks covered narrow layouts, stale responses, retry and duplicate-action recovery. After verified activation, one bounded local canary returned the expected report, closed its exact request and exposed the saved diagnostic through the authenticated application.

This established observability and a safe success path. The canary did not fail naturally, the ordinary supervisor dispatch chain and physical phone were not retested, and browser responses were fixtures. Final phone task errors show classifications; existing per-step progress remains generic. Earlier failed experiments remain negative. No measured performance or success-rate gain is claimed.

The reusable lesson is to preserve precise, bounded evidence before attempting a larger capability improvement. Runtime qualification and historical experiment provenance need separate bindings, and successful cleanup requires its own proof.
