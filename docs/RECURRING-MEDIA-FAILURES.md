# When several failures look like a stalled download

A recovery investigation found that a single visible symptom concealed separate failures in cleanup, source admission, import parsing and library visibility. The useful outcome was a set of bounded repairs and clearer evidence boundaries, rather than a universal promise that every source would become available.

One cleanup filter matched a short low-quality label inside an unrelated audio-codec name. Another treated paused items as stalled and failed to account for intermittent progress. The repair retained native source safeguards, classified active states explicitly, established fresh progress baselines and required repeated measured no-progress intervals. Final ownership checks and durable action receipts kept an uncertain removal from being replayed automatically. Helper and mocked-shell checks covered the original failures; subsequent natural runs demonstrated actual progress resets. A destructive live canary was deliberately excluded.

An import parser required context missing from an original filename. A create-only parent-folder alias preserved the original name and media bytes. Independent acquired-title identity, native quality preservation and retained-source provenance guarded the resulting copy import. This did not authorize forced mappings or invented acquisition history.

An authentication investigation also produced a correction to the investigation itself: concealed API secrets were initially tested as though they were real credentials. Protected authoritative settings disproved that broad diagnosis. The unnecessary edit was reversed, the actual failing connection was repaired, and unrelated notification settings were preserved. A targeted visibility repair remained distinct from proof of a later automatic callback.

The earlier stopped-transfer preservation account is superseded: a later legacy cleanup run removed those jobs, while retained partial-data state remained unproved. Previously available items were excluded from recovery and were not restored.

Negative-only language rules were subsequently activated with combination controls, protected predecessors and stored-state verification. Original-language requirements and unrelated rejection rules remained intact. A bounded player-selection follow-up also became active; its natural check verified an already-correct item without changing it. A subsequent new import remained an explicit untested boundary. Correct stream presence, selected playback tracks and dialogue synchronization stayed separate claims. Proven external captions and episode identity must be preserved before changing a part.

This retrospective does not claim universal source availability, complete recovery, future routing, subjective playback quality or dialogue synchronization. It contains no production configuration or deployment procedure. [Verification boundaries](VERIFICATION.md) remain part of the result.

A capacity blocker revealed another faulty assumption: repeated acquisition records need not advertise identical sizes before metadata arrives. The correction uses fresh ownership evidence and the largest positive estimate while retaining the storage reserve. A real size replaces the estimate when available. Mixed batches still require independent requested-file identity; metadata inspection alone is never reported as completion.


## Retrospective: keep identity stable across different season models

Two metadata providers grouped the same programme differently. Matching their season numbers left requested episodes outside monitoring. The repair carried independently positive episode identities through a durable new-approval outbox, rather than treating season ordinals as interchangeable. Database visibility, later episode publication, manual overrides, existing files and uncertain prior actions each needed their own lifecycle rule. An erroneous upstream identity remained visible as an unresolved case.

A default change also failed to affect existing entries. A bounded migration required an equivalent quality profile and current language-rule definitions, with separate checks for the owner's actual assignment and original language. Unknown write outcomes stayed reserved. A failed negative test exposed mutable preimage references; independent copies repaired that cause. Isolated controls, actual runtime-user artifact inspection, preserved settings and durable natural schedule receipts supported deployment. Genuine later approval behavior remained untested until a real new request occurred.

Subsequent natural imports verified exact destination/source identities and selected native-audio/English-caption metadata. This supersedes the earlier new-import evidence limit, while caption provenance and human timing remain unproved. Recognized short ancillary clips were retained without importing them; unknown extras still held.

The recovery report needed scrutiny too: counting equal native season numbers could conceal missing later episodes. Explicit crosswalks and unresolved-member accounting made the report more conservative. Client disappearance also could not prove payload disappearance, so known roots remained tracked until readable coverage or positive absence was established. These results support bounded engineering claims, not universal availability or a promise that no future failure can occur. No production topology, configuration or deployment procedure is included here.

## Retrospective: completed transfers can fail after downloading

A later investigation correlated a completed source with cleanup events and found that identity-only import failures had triggered removal. A failure label that appeared to indicate a person had acted was also emitted by automation. The repair configured an exclusion for that narrow failure class while retaining unrelated cleanup safeguards. Supported setting readback and later natural jobs were verified; no eligible real item remained to prove the new exclusion during a natural import failure. That boundary stayed visible.

The recovery work also separated missing metadata from conflicting identity. A failed claim that a catalogue had ended was retained when providers disagreed. A separately reviewed fixed current catalogue could establish only its bounded scope, without becoming a general identity fallback or a claim about future episodes.

Repeated read-only connection setup was measured independently from media processing. Reusing a privately owned authenticated connection preserved every physical check and required verified process cleanup, including a failed-command control. Faster inspection did not relax acquisition safeguards. These are retrospective engineering lessons, not deployment instructions or a claim that every request can acquire a viable source.

## Retrospective: acceptance and file identity can disagree

A later repair began with two independently observed identities: the episode a search result claimed to fulfill and the episode its actual file parser recognized. Relative sequel numbering had linked accepted sources to episodes in the original series. Existing files prevented immediate replacement, but relying on their presence would not protect a later retry after state changed.

The bounded repair combined a narrow acquisition restriction, durable quarantine for known conflicting associations and an exact episode-set check for future single-video imports. A file covering several episodes had to match the complete intended set. Multi-file packs retained their separate validation contract; ambiguous relative sequel titles could remain unavailable rather than being guessed into place.

Independent source review and negative controls preceded activation. Normal scheduled runs then demonstrated the known quarantine outcomes while preserving the correct existing episode identities. An unseen-source mismatch was tested through the actual candidate boundary using mocks, without creating a deliberately bad acquisition. The engineering claim is limited to those boundaries: accepted requests, correct episode identity, viable sources and readable synchronized captions remain distinct facts. This retrospective contains no production configuration or deployment procedure.

## Retrospective: a counter reset did not establish data loss

Two maintenance schedules overlapped and restarted the same workload. Removing the redundant restart required more than changing one declaration: the scheduler also regenerated an unrelated dormant declaration. A preservation assertion caught the side effect. A separately reviewed correction restored the intended effective state, and a regression fixture using the actual controller and registry reproduced the original mistake. Neighboring declarations and legitimate maintenance remained protected.

The transfer client later reported much less progress even though substantial files remained. Source-specific state backups and a single stopped recheck established which pieces were valid. Independent current file identities and existing episode identities guarded the subsequent restart of that transfer. Advancing bytes demonstrated recovery; an accepted action alone would not have done so.

A supported shorter checkpoint interval reduced stale-state exposure. Readback accounted for both legitimate omitted defaults and deferred configuration writes, while failed or empty reads remained errors. Natural saved-state updates during real transfer retained the source and selection. Tests also exercised the actual archive verifier with corrupted bytes and metadata, rather than substituting a failed unrelated command.

The evidence did not prove the underlying partfile cause, a shutdown timeout, safe crash recovery or complete delivery. Future schedule boundaries and human caption timing stayed open. These distinctions are part of the engineering result, not qualifications to remove for a cleaner success story. ## Retrospective: ETA did not prove a stalled transfer

An investigation distinguished an actual removal actor from another service that had merely recorded strikes. The observed source had no progress, so actor attribution alone did not show that a healthy transfer was deleted. The classification defect was established separately: a parser discarded byte evidence and treated missing ETA as no progress, including paused and growing inputs.

The repair retired only the flawed stall decisions and the shortcut that repeated their old recorded removals. Other safety checks and historical records remained intact. Mocked tests executed the actual function and verified that old stall records still reached those independent checks. A separate guard treated privacy as unknown until metadata positively established it, and held both removal paths before action intent when that evidence was absent. No destructive live canary was created.

Packaging verification caught its own errors. An intermediate restrictive copy and final permission change were legitimate distinct layers; demanding the final permission in every historical layer was the wrong assertion. The corrected audit required the exact transition and final state while retaining strict content, path and unexpected-file checks. A normal later timer run had empty queues. That established scheduling, not a real eligible-item branch; an automatic startup cycle was not substituted for the later run.

A later content check showed that a plausible episode filename contained the next episode's exact source bytes. Publishing only the missing filename would have duplicated the mistake. Independent identities and complete hashes justified correcting the existing content first, while preserving its original inode and bytes for rollback.

The preferred exchange operation failed safely in a non-media fixture. The record retained the failure without inventing an error cause that had not been captured. A separately reviewed atomic replacement preserved the original and preceded create-only publication. Atomic rename was not described as compare-and-swap, and lost acknowledgment remained an inspection case rather than permission to retry. Registration and player visibility stayed separate from correct bytes.

The earlier finite recovery also progressed from resumed transfer to verified library/player joins and naturally completed request state. That did not prove human caption timing or every future source. A related shutdown candidate was tested in isolated non-media process stacks, where the baseline exited before a delayed checkpoint and the candidate waited for it. Those established-client results did not justify production activation or claims about startup races, enforced deadlines or natural backup behavior.
