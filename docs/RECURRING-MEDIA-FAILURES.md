# When several failures look like a stalled download

A recovery investigation found that a single visible symptom concealed separate failures in cleanup, source admission, import parsing and library visibility. The useful outcome was a set of bounded repairs and clearer evidence boundaries, rather than a universal promise that every source would become available.

One cleanup filter matched a short low-quality label inside an unrelated audio-codec name. Another treated paused items as stalled and failed to account for intermittent progress. The repair retained native source safeguards, classified active states explicitly, established fresh progress baselines and required repeated measured no-progress intervals. Final ownership checks and durable action receipts kept an uncertain removal from being replayed automatically. Helper and mocked-shell checks covered the original failures; subsequent natural runs demonstrated actual progress resets. A destructive live canary was deliberately excluded.

An import parser required context missing from an original filename. A create-only parent-folder alias preserved the original name and media bytes. Independent acquired-title identity, native quality preservation and retained-source provenance guarded the resulting copy import. This did not authorize forced mappings or invented acquisition history.

An authentication investigation also produced a correction to the investigation itself: concealed API secrets were initially tested as though they were real credentials. Protected authoritative settings disproved that broad diagnosis. The unnecessary edit was reversed, the actual failing connection was repaired, and unrelated notification settings were preserved. A targeted visibility repair remained distinct from proof of a later automatic callback.

The earlier stopped-transfer preservation account is superseded: a later legacy cleanup run removed those jobs, while retained partial-data state remained unproved. Previously available items were excluded from recovery and were not restored.

Negative-only language rules were subsequently activated with combination controls, protected predecessors and stored-state verification. Original-language requirements and unrelated rejection rules remained intact. A bounded player-selection follow-up also became active; its natural check verified an already-correct item without changing it. A subsequent new import remained an explicit untested boundary. Correct stream presence, selected playback tracks and dialogue synchronization stayed separate claims. Proven external captions and episode identity must be preserved before changing a part.

This retrospective does not claim universal source availability, complete recovery, future routing, subjective playback quality or dialogue synchronization. It contains no production configuration or deployment procedure. [Verification boundaries](VERIFICATION.md) remain part of the result.

A capacity blocker revealed another faulty assumption: repeated acquisition records need not advertise identical sizes before metadata arrives. The correction uses fresh ownership evidence and the largest positive estimate while retaining the storage reserve. A real size replaces the estimate when available. Mixed batches still require independent requested-file identity; metadata inspection alone is never reported as completion.
