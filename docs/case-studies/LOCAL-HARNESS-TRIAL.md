# A bounded local harness trial

An orchestration demonstration prompted an installation experiment with Turnstone on ARM hardware. The outcome was a separate, file-only local worker trial. It did not establish automatic cloud-supervisor integration or justify replacing an existing task workflow.

The released container architecture did not match the test machine. A native derivative was built from a pinned stable package, with nonroot execution, a read-only application root and a small writable task area. Model execution stayed local. File operations were automatically approved within that task area, while network and command execution were excluded from the trial.

A local worker generated a small interval-merging function. An independent checker, held outside the writable task area, exercised thirteen behaviors. Fresh generation passed them. A separate deliberately seeded endpoint bug then tested coaching: feedback described the failing cases and the worker made a minimal correction. That controlled seed was not classified as a capability failure or a reason for supervisor takeover.

The first coached result was functionally correct, but automatic predecessor backups were absent. Inspection found that the integration had defined mutation wrappers without installing them on the session class. A helper-only backup test would have missed that defect. After repair, installed write and edit dispatch both preserved the exact predecessor; deliberately unavailable backups prevented mutation. A fresh coached trial passed the same behavior cases and preserved the seed hash. The earlier backup failure remained failed in the record.

A second lifecycle defect appeared when streaming output ended before the exact request cleanup receipt was available. A bounded serialized handoff replaced premature rejection. Cancellation was verified through an exact backend-abort receipt, followed by successful readmission. An auxiliary title request completed normally; it was not mislabeled as aborted. Restart retained saved messages and the generated file without replaying inference. Runtime-only stream handoff metadata was distinguished from durable conversation identity.

The evidence had limits. A file-tool fixture did not qualify command execution, distributed coordination, general model difficulty detection or production supervisor integration. A synthetic pending-journal rejection did not substitute for a process-crash experiment. Backend cancellation did not by itself prove stale-response rendering was correct. Browser recovery and error-path observations were treated separately from code behavior; comprehensive upstream UI race qualification remained outside the adoption claim. Shared request accounting also did not establish exclusive resource reservation.

The useful result was a reviewable local experiment with independent output checks and honest failure history. The prevention rule was concrete: when a safety hook wraps a side effect, test the installed dispatch path under both success and enforced failure, then bind the evidence to the artifact that actually ran.

A final evidence review then rejected the state-backup claim. The database option belonged to a different backend, so the application had used its working directory and the backup observer had quietly checked an empty intended location. Saved conversations surviving restart did not prove state isolation or native backups. A consistent snapshot was preserved before a controlled migration, the supported path option was corrected, and a missing configured database became a startup hold. Fresh evidence checked running process file handles, database exclusion from task snapshots, native snapshot integrity, retained conversation identity, a new local file task and another restart without replay. Earlier state-backup claims remained failed; only the fresh evidence qualified the correction.

The user's forwarded browser subsequently exposed another acceptance gap: direct local rendering did not prove forwarded access. The bridge had accepted only its listening port, while forwarding legitimately changed the browser-facing authority. A correction admitted validated loopback authorities with a valid port, required a matching origin when present, rejected duplicate or malformed headers and stripped untrusted forwarding metadata. A target-form negative control also exposed normalization before handler dispatch; validation moved to the original request target. Twenty-seven actual HTTP controls passed, including rejection before upstream calls. A real loopback relay rendered saved history and authenticated reads at desktop and phone widths, with refresh recovery and no new inference. The exact user's browser display could not be inspected remotely; a queued browser-open request was not credited as a displayed page. The lesson was to test the user's forwarding hop before claiming access, while retaining the authentication boundary.


A later authorized access change qualified a private encrypted browser route while preserving every existing route. The bridge admitted one exact encrypted authority and matching origin while retaining validated local forwarding. Thirty-five actual HTTP controls covered valid admission and rejection before upstream calls. Default certificate validation, authenticated reads, saved history and refresh passed through the real encrypted endpoint. An application restart retained both the route and saved state without replaying inference. Automatic application access was a network membership boundary; separate application users were not established.

The attempted configuration export exposed a namespace mismatch before activation: the installed command exported named services rather than the node routing state under review. After two failures, independent source review replaced blind retries with an authoritative state snapshot and a narrowly scoped rollback. An initial mutation lacked operating permission and left state unchanged; existing authorized administrative access applied only the requested route. No broader permission policy was changed.

Discoverability was separately requested. One ordinary home-portal card used a fixed destination outside the existing dynamic link rewriting rules. The first baseline probe reached a different application; its failed byte comparison was retained, and the actual portal source was verified before editing. Removing only the inserted card reproduced the original page bytes. Actual post-script clicks, repeated navigation and refresh passed at three screen widths. A delayed failing status response did not remove or redirect the link, and a real reload recovered. These access checks dispatched no inference. Physical-device connectivity remained unobserved, and the isolated harness did not become a production supervisor integration. The prevention rule was to qualify both the transport endpoint and the real navigation hop while preserving prior routes, state and truthful limits.


## Retrospective specialist qualification

The next authorized experiment addressed the gap between a multi-model recommendation and actual model delegation. Official model cards and stable harness documentation were screened against total weight memory, serving support and the installed package. Two local specialists were exercised through the harness's native named-model delegation, with a bounded coding role and a general-purpose helper. Changing an alias alone was insufficient: the dispatch path checked physical model identity and rejected an identity mismatch before admission. Shared serving allocations were retained; this experiment did not measure an optimal cache configuration or load a whole catalogue of specialist candidates.

A controlled parent delegated a file-and-check task to the helper, then implemented and checked a separate function. Both real model routes were recorded and independent heldout behavior passed. A later fresh extraction task passed without revealing its expected result to the worker. Small matched bug fixes also passed heldout cases and preserved exact predecessor snapshots. One formatting smoke supplied the expected answer, so it was not promoted into extraction-quality evidence. The general worker made protocol mistakes and created an extra check despite a one-file instruction; the coding worker tried missing scripts. Those observations informed clearer tool guidance rather than a premature claim that a local model was incapable. The small trials established provisional usefulness, not statistical superiority or general difficulty detection.

Executable checks were qualified separately from model-written assertions. Scripts ran against a bounded immutable task snapshot with no network, private state or transport access. Inspection found a wrong installed tool-result contract, unbounded output handling, race-prone snapshot reads and incomplete retry suppression. Those defects were corrected and tested through the installed package. After two matching cleanup timeouts, independent review examined native exit timing: the backend had already stopped, while an attached output pipe remained blocked. Continuing to consume and discard bounded chunks during cleanup reproduced successful flood and timeout controls. Merely extending the deadline would have concealed the cause.

Cancellation required exact ownership throughout. A coding request remained connected upstream while its observed native identifier was aborted, then supplied a matching terminal event, end-of-stream marker and EOF before unchanged-backend idle checks established settlement. The general helper used its existing request-correlated admission receipt. Conflicting identifiers, missing terminal or end markers, invalid termination and abort failure controls retained a hold rather than replaying uncertain work. Parent and child check cancellation passed, including a forced child stop followed immediately by a successor. Queued cancellation and interrupted-check ownership were tested at the smallest useful control layer; arbitrary process-crash timing and real backend replacement remained untested.

An exact-history restart assertion failed even though durable results survived: detailed child-step projections were held in an upstream memory cache. Source review confirmed that cold hydration omits those projections and changes an ephemeral handoff field. The failed exact-history assertion was retained; a separately named durable message, parent result, cursor, file and no-replay check passed. No adjacent persistence rewrite was introduced. Default and selected model creation, a controlled connection error with retry, duplicate-click suppression, result refresh and phone-width rendering passed through the real private browser route.

The prevention lessons were to inspect the installed tool and cancellation contracts, distinguish logical aliases from physical identities, keep draining output while settling owned work, and separate transient UI details from durable outcomes. Publisher benchmarks, one failed attempt and a successful worker-written test each answer different questions. Text-only qualification, small samples, physical-device and reboot limits, unmeasured maximal context and cache performance, and the lack of a new production cloud-supervisor bridge remained explicit. This retrospective contains no deployment configuration or current private topology.

### Actual-task failures corrected the qualification story

A real browser-game task exposed gaps missed by small specialist trials. A shell-shaped tool advertised operations that the restricted checker could not perform, and child-agent guidance inherited broader promises. File discovery and offline checking received complete, truthful tool definitions and shared guidance; temporary check artifacts were directed to writable scratch space. Installed-session controls and a live parent-selected workflow with a child repeat established that discovery, syntax checking and behavior checks worked without guessed filenames.

Longer history also revealed that compaction timing had ignored reserved response space. The thresholds were aligned with the permitted input allowance, and only an oversized request rejected before inference received the classification needed for native compaction recovery. Both manual recovery and a later automatic compaction were observed without increasing serving capacity or replaying accepted inference. A saved-session restore path lost automatic file approval; a dedicated restart-and-reopen regression demonstrated automatic writes and edits with exact predecessor backups. A concurrent qualification reached the existing bounded admission wait rather than dispatching; it resumed only its unfinished edit after the other task became idle.

The game task showed why passing worker tests and a reviewer verdict are insufficient acceptance. Invalid test setup was corrected while retaining the win assertion. A repeated oversized review was stopped cooperatively, then narrowed; its limited verdict still missed a same-update terminal-state defect found by an independent browser reproduction. That result was returned to the local coding worker rather than treated as proof the model was incapable. The worker preserved the terminal win before further collision processing, retained existing assertions and added integration coverage. The expanded checks passed and the independent browser reproduction then preserved both the win and remaining lives. Historical errors and limited review coverage remained explicit. The harness interface passed controlled error/retry, duplicate-action, refresh and narrow-screen checks; the generated game remained keyboard-oriented with a narrow-screen layout limitation. This retrospective contains no production configuration, private endpoints, model revisions or deployment instructions.
