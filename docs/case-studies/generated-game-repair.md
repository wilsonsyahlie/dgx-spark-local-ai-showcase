# Repairing a generated game without automatic takeover

A generated maze game had logic, rendering and synthesized audio files, but its entry page omitted the core dependency. The deployed preview reproduced a missing-core error and an absent Start control. A same-task continuation kept implementation with the selected local worker. The supervisor supplied coaching and independent checks; exhausted worker allowance was distinguished from intrinsic difficulty.

Two simulated-browser harness defects were isolated separately: a fake element lacked a real DOM method used by direction controls, and the terminal fixture preset game-over status before a frame rather than causing the transition during a tick. Scaffolding and stimulus corrections retained every original assertion and preserved game logic.

The short deployed preview then exposed clipping. One attempt stopped before CSS inference on the unchanged resource guard. A later local CSS change still overflowed because a nested three-button row became a vertical column; its sound control also became smaller. Source review and real geometry rejected that output. A temporary browser positive control established a minimal horizontal-row correction with the original sound target before further local coaching. Existing readable overlay and canvas aspect ratio were preserved.

Cold model loading and restoration dominated latency for these small changes. A later restoration-only guard breach was retained separately from the earlier candidate-start failure; exact physical closure and restored readiness were required before continuation. The correction did not weaken resource guards, substitute a worker, change model defaults, or treat infrastructure failure as permission for takeover. Bounded additional local coaching belongs inside the existing allowance when source review catches a simple error.

## Limits and prevention

Native nonzero audio waveform evidence can establish generated sound, but cannot prove what a person heard through physical speakers. Emulated touch does not qualify a physical phone. A separate application event-read rejection is outside game assets; successful game asset loads must be checked without changing preview protections. No training, broader model ranking, maximum-context result or cancellation requalification is claimed.

When files exist, check dependency wiring and the actual rendered output. When a harness fails, reproduce its stimulus and preserve meaningful assertions. When controls clip, include nested layout, HUD, gaps and padding in the height budget and verify real rectangles. When recording operational diagnostics, project explicitly safe fields instead of dumping a state store. Delivery requires an accessible playable result as well as passing checks.
