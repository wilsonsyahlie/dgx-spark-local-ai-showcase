# When a model benchmark stops before the model is ready

A retrospective local experiment used a voxel goose riding a bicycle as a practical coding challenge. Each arm had the same core instructions, tools and a fixed time budget. A working rendered scene was required before comparing speed.

The incumbent ran out of time and left a scene that crashed before drawing its subject. The candidate's loading process stopped at a machine-wide swap safeguard before readiness. A separately reviewed retry used an explicitly revised experimental policy while preserving the prohibition on candidate swap and the other resource checks. It progressed further, then crossed the revised ceiling too. No candidate coding task began.

That result supports neither a speed improvement nor a conclusion that the model could never fit. Machine-wide swap growth can occur while the candidate's own counter stays at zero; aggregate measurements do not identify the source or establish causality. A partial load and spare reported memory do not prove full capacity either. An initially plausible prefetch explanation was rejected after checking the actual loader and startup record.

The useful engineering result was narrower: two recovery checks were repaired. Definition comparison stopped treating qualified order-independent fields as meaningful changes, while still rejecting duplicate and changed semantics. Recovery accounting used the supported cross-process token path rather than an owner-restricted lookup. Focused negative controls and the real isolated protocol verified those boundaries. Both actual cleanup paths then confirmed one restoration of the original setup, with history and existing artifacts preserved.

The failed model evaluation remained a failed evaluation. No working new scene, model promotion, speed ratio or general quality gain was claimed. Long-running stability and physical-device acceptance remained untested. The retained evidence separated restored availability from the unresolved loading problem.

The lesson: distinguish time spent investigating from a working model, a correct artifact and a useful upgrade. Keep failed attempts when test policy changes, verify recovery against the actual authority contract, and report the exact boundary that passed. Safer testing is valuable, but it is not itself a performance upgrade.
