# A scene that rendered was still not ready

A local coding assistant recreated an animated voxel bird on a bicycle from a public visual example. An image reviewer compared real screenshots with the reference, while a separate supervisor checked the browser output and sent measured feedback. The creator retained ownership of the code.

The first result showed only a sky. A shader check passed, but a JavaScript naming error prevented the scene from drawing. Correcting that exposed a second defect: the desktop camera cropped the bird. Fitting the camera to the actual mesh helped, but the phone view then revealed a nearby cloud covering most of the subject.

Each failure changed what acceptance needed to observe. Geometry checks addressed cycling mechanics and recycling. Browser checks addressed visible framing, controls, refresh and responsive presentation. A digest connected checked source with the delivered artifact. Failed versions were preserved.

Image review helped identify missing content, but one report simultaneously praised and rejected the framing. Visible evidence had to settle that disagreement. The final comparison was a qualitative account of similarities and remaining differences, not a claim that a second model could certify visual quality or infer smooth motion from a few stills.

Two resource-protection interruptions prompted an explicit owner request to fix the reserve policy. A reviewed correction distinguished room needed before loading from headroom needed after loading. The real combined workload and a warm repeat succeeded with other protections intact. Earlier interruptions, small host swapping and gaps in an initial observer were retained; recovery did not erase them. The result was a supervised recreation with bounded checks, rather than evidence of autonomous first-attempt success or a broad performance breakthrough.

This retrospective contains no production configuration, private screenshots, deployable instructions or live-system identifiers.
