# Put specialist concurrency on the intended host

A team setup initially reused a model on the wrong machine. The owner corrected the intended serving location and authorized releasing an idle backend to make room. A dedicated local batched server replaced the intermediate route while preserving the existing primary and message histories. A fine-tune intended to reduce refusals accepted a benign original-code game request; this is one measured behavior, not a promise of zero refusals.

Preparation exposed two deployment assumptions: the image's default entrypoint differed from an existing container's override, and a snapshot directory depended on blob symlinks outside its mount. Failed instances and diagnostics were retained. Explicit entrypoint selection and a complete read-only cache mount corrected the causes. Readiness was measured after initialization rather than inferred from a request acknowledgement or a timeout.

Six synchronized short requests reached six running sequences. Shared token capacity supports fewer maximum-length histories than the configured slot count. The evidence therefore qualifies bounded concurrent work, not six indefinitely simultaneous full-context conversations. An actual asynchronous coding handoff created and executed a small movement check, completed the recipient's turn and returned a coordinator relay. Other roles returned native replies.

The old workstation model was measured unloaded and its dedicated bridge retired. An immediate assertion lacked a preserved failure-time status; its transient cause remains inference. The stop was not replayed, and later read-only evidence established retirement. Backups preceded controls, while their final manifest came afterwards; this is recorded as a timing limitation.

A desktop can display the team while execution remains on its serving host. The remote client used an unchanged official source tag and local signing, with native encrypted connection storage and a key-authenticated private forward. It is not a published vendor-notarized remote-only release. Signature validation initially failed before activation; a protected bundle archive preceded the correction.

Independent review stages cancelled by the owner were recorded as waived. Broad output quality, zero refusals, sustained maximum-context concurrency, physical acceptance, reboot and unattended network recovery remain unqualified. This retrospective contains no current private topology or deployment instructions.

A real desktop message returned a correct synthetic answer on the serving host. Refresh and cold client reconnection preserved it; role/group discovery, native encrypted storage, a narrow layout and invalid-token rejection passed. Initial selector/draft assumptions failed before a real submit and remained recorded.
