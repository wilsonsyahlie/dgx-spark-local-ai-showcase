# A complete label did not prove complete coverage

A repair of gaps in an existing media collection exposed a useful distinction:
source titles describe intent, while actual file inventories establish coverage.
Two apparently complete releases held only an early subset. Positive file and
episode identity checks prevented those labels from becoming completion claims.

Preserving an existing collection also required more than disabling upgrades.
Unwanted source files needed explicit import exclusion as well as zero download
priority because shared boundary pieces could still create filenames and bytes.
An unfamiliar acknowledgement was reconciled against the original operation
rather than replayed. A later health check required timely new bytes and
availability, rather than treating an advertised peer count as success.

Completed-file qualification and fresh installed-file hashes verified the
recovery. The final source was qualified before handoff, with exact path-to-episode
preview and current conflict checks. Installed-file hashes matched source proofs,
and existing-file identities and descriptors remained intact. Unique episode,
file and path mappings agreed across the
catalogues. A natural scan marked the request complete. A checker assumption
that approval and completion shared a state was corrected against the deployed
contract; unfinished states stayed rejected.

No broader recurring repair system or global policy change followed from this
single repair. These technical checks do not establish human playback, catalogue
duration agreement, dialogue synchronization or universal future reliability.

The general lesson is to keep acquisition, transfer, import and user-visible
availability as separate evidence boundaries. A successful command or a
complete-sounding name cannot substitute for the boundary the user needs.


A completed-source tracking warning also cleared without another mutation. A
prepared acknowledgement first held because the cache was already absent, then
held when the client record disappeared naturally. Positive absence checks and
current installed-file preservation were kept separate. The cleanup actor was
not attributed; no acknowledgement, client deletion or new retry was performed.
The changing state made the proposed action unnecessary.
