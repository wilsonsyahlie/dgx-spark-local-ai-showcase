# Repairing captions while preserving media

A language admission rule prevents some future mistakes, but previously admitted media needs a separate authorized repair. Two scoped repairs showed why availability, episode identity, timing and player selection require different evidence.

One season had only an unwanted subtitle language and lacked a requested-caption profile. A narrow profile correction was backed up and verified. Provider discovery returned no qualified result; a missing identity-resolver setup and a throttled provider were recorded without changing global credentials. Publicly indexed caption attachments supplied matching dialogue without replacement videos.

A release with the right episode number still omitted preview clips joined onto the local videos. The repair qualified main episodes and their separate preview sources, preserving the original attachments and failed staging versions. Plain text conversion retained dialogue and translated songs while omitting identified animated graphic fragments.

Initial timing checks assumed translations shared cue boundaries. A split sentence in one translation corresponded to a longer cue in another. Independent review supported interval agreement and semantic anchors; onset differences remained diagnostic. Animated signs also distorted a preview's correlation, so a dialogue-only reference corrected that segment. Small final display overhangs received individually reviewed end-only bounds, preserving all text and cue starts. These checks were described as subtitle-window evidence, not independent audio proof.

The other repair initially looked like severe drift. The player had selected a different show's downloaded caption track, while the local sidecar belonged to an older episode whose season numbering was reused. The correct newer episode's story and absolute identity were established before any synchronization. A matching caption source retained every line and received a small uniform adjustment against native audio using offline voice activity detection. Beginning, middle and late dialogue samples agreed with the embedded reference.

Player acceptance included the selected caption's served content hash, native audio choice and unchanged video identity, size and modification time. A language label alone would have accepted the wrong track. Original captions and state snapshots were retained for a narrow rollback; restoring an entire live database would erase unrelated intervening work.

An online snapshot opened a database through a different filesystem alias from the application. Stale journal handles and a metadata error appeared afterward. This association supported a scoped service restart after independent review, while exclusive causation remained unproven. The original metadata operation then passed and profile assignments remained unchanged. The prevention lesson is to use the application's native backup or preserve its active mount and service identity, rather than deleting journal files.

A uniquely scoped release rule screened future downloads for established caption sources and explicit new-season or absolute numbering, while retaining actual audio/caption inspection at admission. Preliminary boundary controls included an older episode beside a high-resolution number. Native parser checks mapped next-episode examples to the correct new season. Native release evaluation distinguished required-term decisions from earlier parser holds; it did not credit early rejection as execution of the later matcher. A legacy scalar API split a regular expression at a comma, so readback held activation until one complete expression was supplied as an array item.

Automated checks and served-caption hashes establish a repaired library and selected tracks. They do not prove complete human playback, perfect line-by-line timing or the next unreleased episode's future transfer. Conservatively holding an unsuitable source remains preferable to admitting captions for the wrong episode.
