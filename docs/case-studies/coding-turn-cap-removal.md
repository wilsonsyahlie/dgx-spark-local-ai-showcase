# Removing an explicit coding-turn cap

A coding worker reached an explicit tool-iteration budget before completing verification and preview delivery. An owner requested removal of that cap. The smallest change used the application's supported unlimited setting for that worker, preserving other roles and generation parameters.

Verification checked the installed agent factory and its shared iteration budget. A deterministic fixture exercised the real conversation loop beyond the old cutoff and obtained a normal final answer. The former cap remained a negative control, and interruption still stopped an unlimited turn. A small fresh native reply verified the local route remained usable.

Configuration comparison found only the requested field changed. Existing messages and other profile configurations were preserved. The active-session view contained no matching cached coding sessions, so no old sessions were rebuilt or active work interrupted. Backups and a supported rollback were defined before activation.

One proof extractor expected output on the standard stream, while an imported server routed it to the diagnostic stream. The retained proof was recovered from that stream without repeating the test or treating an empty file as failure. Process checks likewise used the actual listener identity rather than assuming a process-name filter was complete.

This removes an iteration-policy cutoff; it does not prove a model will always finish its task. Context, output, tool deadlines, interruption and resource boundaries remain. Sustained real-model behavior beyond the former cutoff, physical-client acceptance and reboot behavior were not tested. Preview delivery still needs an actual publication receipt and returned link.
