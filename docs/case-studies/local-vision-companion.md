# Available memory did not settle a vision-worker decision

A project trial explored separate local image analysis alongside an existing assistant. The first small candidate worked on real screenshots, but that did not prove it was the best available model. An operator correctly challenged a conservative memory assumption and prompted a larger-candidate fit investigation.

Two different failures mattered. First, a restrictive temporary directory prevented a runtime support library from loading. A small causal experiment isolated that issue. During the next model-construction attempt, host swap grew despite an available-memory reading that still looked comfortable. That reading included reclaimable cache; it was not a promise that every allocation would avoid paging. The record did not prove which allocation initiated the swap or establish a hardware impossibility.

A slow shutdown response compounded the problem: the candidate crossed its guard, but a graceful stop delay allowed pressure to reach the existing assistant's guard too. The assistant was recovered with its previous settings. Emergency handling was revised so an owned experiment could be terminated before optional probes or diagnostic writes, with exact process closure proved before releasing accounting state.

The engineering lesson is to distinguish checkpoint size, startup peak, steady residency, available memory and actual free memory. A successful small candidate is useful evidence, not universal superiority; a failed loading attempt is not a complete capacity benchmark. The smaller image worker was subsequently connected through the normal assistant path. Actual chat/tool routing, concurrent text and image requests, exact cancellation, an independently restarted worker and preservation of previous conversations passed. A declared emergency-stop exercise closed the owned worker and accounting state in under a second while leaving the main process intact. The full cold assistant turn still took several minutes despite a quick warm image response, so this was a capability integration rather than a broad speed claim. A backup procedure also missed a fresh pre-check database snapshot; the raw copy was labelled invalid, current protection was corrected and earlier consistent history was checked rather than pretending the missed step had passed. Sparse screenshots, literal text formatting and continuous motion also have different acceptance boundaries.
