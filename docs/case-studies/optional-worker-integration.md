# An optional coding worker required end-to-end qualification

The owner wanted a researched local coding candidate available in an automatically supervised task interface. The resulting selection applied only to new tasks and stayed immutable within an accepted task. The original default and old local work were preserved. Planning, independent checks and focused coaching remained the supervisor's role; application implementation remained local, with separate file authorship and predecessor backups.

A fresh bounded counter project demonstrated the candidate path. The local worker authored both application files. The supervisor prepared and qualified an independent behavioral checker, proved that it rejected a deliberately broken boundary case, and passed all twenty-seven final cases against the actual application. Browser acceptance exercised buttons and keyboard behavior, the nonnegative boundary, exact downloaded bytes and refreshed previews at desktop and narrow widths. Requested model and accepted supervisor effort remained distinct from actual worker state. This qualified one useful workflow, not broad model superiority or a new default.

Real execution exposed two infrastructure assumptions that isolated success had hidden. A read-only state query needed unavailable journal sidecars under the deployed service boundary; widening filesystem permissions would have weakened the authority model. Authenticated historical proof replaced that assumption. Then serving metadata became available while startup warmup was still unfinished. A request sent during that interval reached its deadline without application output. Readiness was corrected to require initialization evidence bound to the exact owned process incarnation, alongside existing identity, capacity and cancellation checks. Generating health canaries and longer inference deadlines were not used as substitutes.

Recovery exposed a third gap: an isolated credential fixture had privileges absent in production. The real least-privilege daemon correctly denied tokenless orphan reconciliation. The fixture was corrected, and recovery used existing saved-token release authority only after exact physical closure. Missing tokens continued to hold. A lost acknowledgement was observed against the saved operation instead of replaying it. No admission privilege was widened.

Physical closure was recorded separately from successful inference completion. Missing stream termination remained unknown; the failed task was cancelled with a typed, independently validated closure receipt. Exact old process, container and lease evidence survived recovery, as did the original failed settlement and retained hold history. Both intake and controller authority were fenced during corrective replacement. The restored original had to be initialized before ownership release. An earlier replacement interval lacked the later fencing and remains an explicit retrospective limitation.

A real compaction stress witness reduced context but repeated earlier reads, exhausted its bounded tool budget and produced no final artifact. That failure was retained rather than rescored as a memory success. Exact-token overflow separately failed before backend inference, with correlated parent and gateway receipts. A focused coached witness is reported separately in the verification record; neither it nor a small project establishes saturated-context quality. Guided execution does not train model weights or prove permanent learning.

A later active cancellation exposed another readiness assumption: a valid timestamp used fewer fractional digits than the parser expected. The correction validates the calendar and compares integer nanoseconds across supported precisions. A replacement attempt stopped before any destructive effect when the watchdog refreshed telemetry; the continuation retained that guard evidence and allowed only the measured sample change while preserving every ownership and operation field. One explicit inspection of the existing stopped task restored the initialized original and released ownership; the original automatic restoration failure remains a failure. A fresh original-default job independently passed local authorship, exact output, download, refresh and settlement checks. No uninterrupted corrected-runtime active cancellation witness is claimed.

The engineering lesson is to qualify the complete user path and its least-privilege recovery, distinguish readiness from metadata health, and bind completion claims to actual artifacts. This retrospective excludes private data, current deployable topology, precise identifiers and operational commands. Physical-device, reboot, broad ranking and maximal-context quality remain outside the evidence.
