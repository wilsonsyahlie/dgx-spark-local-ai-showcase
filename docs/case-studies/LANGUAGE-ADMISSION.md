# Language admission as two independent requirements

A playback complaint exposed a policy gap: audio-language filtering did not establish that the requested caption language existed. Release labels were insufficient evidence. The correction separates audio and dialogue-caption admission, then verifies the actual media streams before accepting a missing library item.

Lifecycle inspection rejected an apparently convenient import hook because replacement could remove a predecessor before the hook ran. A bounded verifier instead preserves native mapping and rejection decisions, checks every video in a candidate, and holds replacements and uncertain outcomes. Durable intent precedes submission; completion requires checking resulting files. Unknown commands are reserved rather than replayed.

Request routing had another gap: privileged accounts skipped ordinary override rules. A minimal guard was exercised through the actual request method with isolated dependencies. Recognized animation requests use the protected admission path for every role; missing or ambiguous configuration fails before persistence. Ordinary requests retain their routing.

Focused checks covered language absence, forced or signs-only captions, mixed packs, mapping errors, source mutation, uncertain submission, scheduling bounds and role-dependent routing. Real compliant and noncompliant files were probed. Natural quiet runs established scheduler continuity, not delivery of a notification.

The evidence remains bounded: language metadata can be wrong, catalog classification can be incomplete, existing content was not repaired, and a genuine new download/import/playback cycle had no eligible candidate and was not run. External-caption-only content and replacements remain conservatively held. Repository publication is a retrospective record, not a deployment mechanism.

When caption language matters, treat it as an independent acceptance requirement. Inspect destructive lifecycle ordering before choosing hooks, test privileged paths explicitly, and distinguish command completion from verified results.


## Retrospective: distinguish policy, provenance and player choice

A recovery investigation separated three concerns that had been conflated: whether an acquired item was eligible for historical recovery, whether its original audio and full English captions met policy, and which tracks the player actually selected. Two previously completed items passed repeated source qualification and natural destination verification after a minimal eligibility change. Older external captions were retained while the player selected the release-matched embedded track. Synchronization was not measured.

A separately scoped original-language exception retained strict owner identity checks and fail-closed parsing. A real native acquisition subsequently passed the same independent admission path. Dedicated selection and player preferences preserved other owners' rules. Manually selected packs remained explicit operator fulfillment, rather than being given invented acquisition history.

Two failed approaches remained visible. An asynchronous metadata-stop transition required observed-state reconciliation, and a helper review arrived after activation despite prior plan review. Later verification and future hardening did not erase that procedural gap. Repeated search-admission holds also revealed disabled monitoring on still-requested missing items; repair preserved exact preimages and readbacks rather than changing global defaults.

This is a bounded engineering checkpoint. Wider source availability and transfer recovery continued separately; a search acknowledgement, selected caption or successful import does not establish universal completion, subjective playback quality or synchronized dialogue.


## Retrospective correction: establish authorization before recovery

The earlier monitoring-restoration description was based on a wrong assumption: an approved request with missing files was treated as pending even though it had previously been marked available and unmonitored. A review repeated that interpretation. The user clarified pending-only scope, and the recovery returned those monitoring settings to their recorded originals, stopped only positively identified new incomplete transfers, and preserved data and history. Fresh reads confirmed the corrected states. Deleted items remained excluded.

The caption account also required correction. Calling external captions older had not been established. Actual comparison found matching normalized cue text with only a uniform negligible timestamp difference. That supports consistency with the release; it does not establish human dialogue synchronization.

A narrow subtitle-label matcher correction passed native source-selection integration while retaining all other admission controls. The wider recovery remains ongoing. The engineering lesson is to test authorization, lifecycle interpretation, provenance and fulfillment separately; successful review cannot substitute for user scope.
