# Language admission as two independent requirements

A playback complaint exposed a policy gap: audio-language filtering did not establish that the requested caption language existed. Release labels were insufficient evidence. The correction separates audio and dialogue-caption admission, then verifies the actual media streams before accepting a missing library item.

Lifecycle inspection rejected an apparently convenient import hook because replacement could remove a predecessor before the hook ran. A bounded verifier instead preserves native mapping and rejection decisions, checks every video in a candidate, and holds replacements and uncertain outcomes. Durable intent precedes submission; completion requires checking resulting files. Unknown commands are reserved rather than replayed.

Request routing had another gap: privileged accounts skipped ordinary override rules. A minimal guard was exercised through the actual request method with isolated dependencies. Recognized animation requests use the protected admission path for every role; missing or ambiguous configuration fails before persistence. Ordinary requests retain their routing.

Focused checks covered language absence, forced or signs-only captions, mixed packs, mapping errors, source mutation, uncertain submission, scheduling bounds and role-dependent routing. Real compliant and noncompliant files were probed. Natural quiet runs established scheduler continuity, not delivery of a notification.

The evidence remains bounded: language metadata can be wrong, catalog classification can be incomplete, existing content was not repaired, and a genuine new download/import/playback cycle had no eligible candidate and was not run. External-caption-only content and replacements remain conservatively held. Repository publication is a retrospective record, not a deployment mechanism.

When caption language matters, treat it as an independent acceptance requirement. Inspect destructive lifecycle ordering before choosing hooks, test privileged paths explicitly, and distinguish command completion from verified results.
