# Combine small edits and checks, then measure the full turn

A simple coding repair could spend several agent turns moving between inspection, backup, editing and verification. A bounded action combined the existing protected writer with declared function checks, so an eligible repair could inspect once, edit and check once, then report. It made no model calls of its own. The intended maximum was three main model calls.

The action accepted a strict data plan rather than generated shell commands: a source fingerprint, a few uniquely matched literal replacements and typed function cases. It compiled proposed source before mutation, retained the actual predecessor through the existing protected writer and bound results to freshly read source. Claimed operation identifiers could not be replayed after an uncertain acknowledgement. Failed checks retained the changed source and its backup rather than silently restoring it.

Independent review identified two concrete defects before activation. A newly created state directory required synchronizing its parent before committing intent. Also, disabling new bytecode-cache writes did not ensure that existing stale bytecode would never execute. The action was changed to compile the exact bytes whose fingerprint it checked. Negative controls exercised both cases. Twenty-two control groups passed in both development and mounted runtime environments, followed by a real protected-writer integration check.

A neutral fresh repair request automatically selected the action. Its eleven declared cases and fourteen independently frozen function and command-line cases passed; only the intended expression changed. The complete durable user-to-final turn took 52.235 seconds, with a separate 54.093-second lifecycle. It used four main model calls, including an extra source read after the action passed. The maximum-three target failed. This was a different task from earlier timing work, so no matched speed percentage or general performance improvement was established.

Correct code and accurate prose remained separate requirements. The final model explanation gave a wrong example of the original behavior even though the repaired artifact passed independent execution. Direct evidence of the original constructed prompt was unavailable after the runtime closed; mounted guidance identity and observed automatic selection did not become a substitute claim. All new request operations settled, with a proven abort distinguished from completed responses; older bookkeeping debt was unchanged.

This action was retained only for understood, authorized small Python functions without external side effects. It executed code with the user's privileges and was not a filesystem or network sandbox. It did not certify browser behavior or general integration, detect arbitrary secrets, or eliminate the existing unrelated-writer race. Ordinary model settings stayed unchanged. The engineering lesson was to report the achieved bounded functionality and the missed efficiency goal separately, rather than turn a convenient helper into an unsupported performance claim.

This is a retrospective, non-deployable account; it contains no operational configuration or procedure.
