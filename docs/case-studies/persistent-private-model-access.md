# Turning a short model experiment into usable private access

A successful local inference trial had left its model stopped. The owner wanted an entry from the existing home portal that worked over the private network. Adding a link alone would have pointed to a dead server. The scoped follow-up supplied a persistent control page and the inference engine's native chat interface, with explicit Start, Open chat and Stop actions. It did not promote a coding worker or change existing inference defaults.

The browser and network connection were deliberately separated from model ownership. A local manager saved launch intents and tracked exact session identities. Closing a tab or restarting the manager, access proxy or private tunnel did not end the same model session. An uncertain launch was fenced rather than replayed. Stop receipts required delivery to the intended session, so a crash between saving an intent and writing its stop marker could not falsely report success.

The initial review also found that an early rejected HTTP body could be interpreted as another request on a reusable connection. The access boundary was corrected before activation, with strict framing and one request per connection. A raw-socket regression proved that an embedded second request did not reach lifecycle control. Native configuration changes and tool execution remained outside the exposed chat interface, and internal credentials stayed server-side.

Persistent use required stronger device exclusion than the earlier short trial had established. A durable ownership record was checked independently of the cooperative mutex, both before and after acquiring it. Even a stale or malformed record blocked admission. Retirement required the owned process job to be empty, device resources to be released and the exact original idle services to be restored. A failed first interruption test targeted a launcher instead of its actual child owner; review identified the identity mismatch. The corrected test used the owner recorded in the durable contract. While its recovery controller was paused, the owner exited, the mutex became free and the candidate process identity remained observable; competing work was still refused. Recovery then closed the job, restored the same original process identities and retired only its own record.

An actual home-portal click opened the private controls and native chat. A streamed arithmetic response, desktop and narrow layouts, loading, duplicate actions, chat refresh and recovery checks passed. Fresh startup after the interruption, rejection of another active Start, initial chat assets and a narrow-layout Stop also passed. The final model was stopped with its controls ready for the owner's next use and existing services idle. The earlier context and memory profile was preserved. Output limits were disclosed in the interface rather than silently appearing unlimited.

These checks establish usable private access and the tested recovery ordering. They do not establish physical-device behavior, reboot or logon-trigger behavior, long-context quality, sustained throughput, concurrent-user fairness or recovery from simultaneous loss of both ownership monitors. That double fault remains blocked pending evidence-based recovery. This retrospective contains no current operational topology, private artifacts, deployable commands or service configuration.
