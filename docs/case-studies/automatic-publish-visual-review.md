# Make visual checks part of publishing

A link opening successfully did not mean the generated scene rendered correctly. Repeatedly asking a person for screenshots and close-ups made that gap expensive. The improvement was to place a bounded visual check inside the existing publishing workflow.

The assistant now captures full desktop and narrow views plus a detail chosen from actual pixel structure. It labels supplied reference images separately, closes its browser before local image analysis, and receives provisional repair feedback. It can make two repair revisions without another screenshot request. The budget belongs to the task, so changing source or reference does not restart it.

The harder engineering work involved truthful evidence. Interrupted work must not silently repeat an uncertain model call. Reusing a review requires the same immutable entry and assets, unchanged review inputs and intact screenshots. Earlier findings must survive a later failed check. A separate watchdog must close browser descendants even if their owner is force-stopped. Independent review and focused fault tests shaped those boundaries.

One ordinary creator request reproduced a real earlier rendering crash, received automatic feedback, backed up and repaired the source, then published a new version without follow-up steering. Browser captures then recorded no errors, but the image service was unavailable, so visual acceptance remained unresolved. This verified repair feedback without establishing successful image-model qualification. A separately approved measurement found that shrinking a startup limit enough to fit current memory would understate observed demand. The original policy remained unchanged, and the image review remains unfinished. A temporary creator probe also missed its directory boundary; that limit was recorded rather than hidden. This approach helps catch obvious faults without claiming that a small image model can certify beauty or perfect reference matching. Sparse screenshots still cannot prove every animation frame, controls or physical-device behavior. Failed or exhausted checks remain visible alongside a real preview instead of becoming a false pass.
