# Qualifying a native mixed-quant runtime

A model's reported GPU footprint on one platform did not establish its memory demand or compatibility on another. An interoperability experiment therefore kept the exact candidate and tested package integrity, small numerical operations, reference comparisons and ordinary execution separately. Narrow precision corrections passed a frozen small-model reference; they were not presented as full-model success.

The service harness also needed real execution tests. Hardened startup exposed an intermediate setup process, a native option differed from the expected spelling, restart readiness raced a temporary socket, and a delayed response did not mean a request had failed. Durable ownership and original-request settlement let these failures be investigated without replaying work or discarding their evidence.

A cleared-memory small execution passed and its original workload was restored. Earlier resource-guard terminations remained failures. A later full-size execution produced a correct short answer, but a subsequent dependency check rejected an incomplete inventory. Exact library and loader-cache checks passed retained-mapping and negative controls; a fresh trial then stopped on its unchanged resource guard before answering. Repeatable safe execution and usable deployment remained unqualified. A successful build, small completion, advertised context ceiling and successful recovery were kept as distinct results.

The engineering lesson is to record measurements before subsequent checks can fail, refresh state after a component changes its ownership receipt, and preserve a safe refusal as a refusal. A small test is useful evidence only when its limits remain visible.

Original workloads and policy were verified restored after the final rejected trial. This checkpoint closes the bounded experiment and its recovery; it does not deliver a selectable production model.
