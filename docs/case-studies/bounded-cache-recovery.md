# Recovery evidence without a permanent-repair claim

A previous performance experiment ended at a resource-protection boundary before producing an implementation. The recovery work kept that failed result intact rather than restarting it and reporting a replacement score.

The engineering lesson was to distinguish available memory from memory that is immediately free. A bounded, independently reviewed cache-reclaim operation demonstrated substantial recoverable headroom while preserving the running backend and its protections. The operation targeted a verified accounting group, made one request without retry, and checked actual memory movement and process closure afterward. Shared cache accounting and possible refault costs remained explicit limitations.

This was a manual mitigation, not proof of the earlier shutdown's cause. No periodic cache policy, relaxed limit or automatic retry followed from the result. A finite numeric observer and a fresh useful-work task provide separate evidence of behavior after recovery; neither can turn one successful run into permanent prevention.

The validation workflow preserves exact task identity, uses an independent deadline, checks settlement and grades the actual rendered artifact rather than a success message. Desktop and narrow-screen behavior, controls and newly served bytes require independent evidence. Detailed operational artifacts and deployment instructions are intentionally excluded from this retrospective.

A verification-parser mistake also reinforced a practical rule: inspect a manifest's real schema, require exact expected path sets, and classify excluded records explicitly. A failed assertion stays visible rather than being weakened to obtain a pass.

The bounded task reached its original deadline. The backend remained available, but the generated scene failed independent visual review and was not delivered as complete. Its own checks also retained failures. A preservation-only intervention made the attempt assisted; recoverable earlier file contents did not retrospectively establish full backup compliance. Recovery, task quality and permanent shutdown prevention therefore remained three separate outcomes.
