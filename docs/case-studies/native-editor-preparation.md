# Qualifying native tools without claiming a finished boss encounter

A high-fidelity boss encounter prompted a move from a browser plan to an experimental native editor route. The completed preparation work established that local asset-authoring and compiler tools could execute. It did not establish that the editor or game worked.

## Why artifact evidence mattered

An early Blender run raised a missing-dependency exception despite a normal process exit. A private dependency and explicit script-failure handling repaired the authoring path. Reopening the actual saved scene exposed a second boundary: the ARM package lacked its denoiser. Disabling that unsupported feature allowed a real CPU render. Export diagnostics also identified unavailable optional compression; independently parsed ordinary mesh exports remained valid.

The preview showed textured ruins and a many-limbed creature, but its anatomy and face were visibly primitive. It remained a procedural draft below the requested quality. The exports contained transform pivots, with no skeletal skins or animation clips. A successful model export cannot stand in for character animation or visual acceptance.

## What the checks established

Package and runtime archives were checked against upstream manifests, then the extracted tools were actually executed. The scene was saved, reopened and rendered, and mesh exports were inspected independently for bounds, indices and embedded images. Two native compiler builds ran 27 isolated combat assertions.

One combat fixture had confused an idle guard with an unshielded damage state. Correcting the setup preserved the intended mechanic. Independent review reproduced the preserved earlier fixture failure and identified an assertion-count underreport, which was then corrected. The later reproduction was identified as such instead of presented as an original retained log.

GPU enumeration established device visibility only. Community port claims and link-satisfying stubs did not establish real editor rendering or importer support. License-gated source was initially unavailable; a later owner-completed invitation allowed authenticated access and a pinned isolated fetch. Two upstream line-ending blobs made a clean-status check fail despite unchanged raw bytes. The exception was verified without rewriting the files or suppressing arbitrary changes. No unofficial source substitute was used. Interactive controls, materials in the editor, audio, performance, a packaged fight and final fidelity remained unverified.

## The engineering lesson

A relocated development link also lacked its already-installed runtime; adding matching bytes to the missing local target repaired real linkage without changing the original link or system library. A source-fetch scope label and missing active-limit evidence were explicitly qualified, then later-stage design required live enforced controls before work.

Separate task tools and child-process environments avoided changing the existing package registration or sampled service processes. Backups and scoped recovery preserved the authored work. The preparation record stayed explicit about the unfinished outcome rather than turning prerequisites into a completed-game claim.

A native engine can supply useful rendering and animation tools, but it cannot make rough assets meet a high-fidelity brief. Acceptance still needs the actual imported scene, visible character quality and a playable encounter.

The owner later chose a different editor route, superseding the experimental build before activation. Saved source and authored assets were retained. Future game tests must close their owned processes after every outcome and verify exit; that cleanup was a requirement, with live implementation and game acceptance still pending.
