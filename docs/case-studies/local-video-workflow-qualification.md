# Qualifying a local video workflow on a consumer GPU

A request prompted by a public video demonstration required more than downloading a checkpoint. The existing interface already supplied the necessary native nodes. The scoped change added a publisher-verified mixed-precision checkpoint, its recommended distilled adapter and separately named text-to-video and image-to-video starter graphs. Existing encoder assets were reused. The full converted checkpoint was kept distinct from its conversion adapter, avoiding accidental double application. No interface upgrade, cloud inference or default model replacement was needed.

The owner authorized releasing the unused resident model through its supported control. A later system-memory check refused generation before submission. Measurement identified an abandoned read-only diagnostic, whose deep serialization of provider-annotated text had consumed substantial memory. Exact process identity was revalidated before closing only that diagnostic. Actual memory recovery and service health were measured afterward. Large inline Windows commands also failed; successful small transport controls and hash-verified file deployment were kept distinct from a timed-out large-source test.

The browser initially exposed canvas state before native registration and workspace initialization had settled. Waiting for the actual application lifecycle and then comparing every browser-generated class and input against the intended graph qualified the user path. Saved workflows were opened through the native library, refreshed and checked at desktop and narrow widths without missing nodes, page errors or document overflow. A fixture reporting failure after saved assertions was recorded separately from the passing graph evidence.

Both small live modes produced fully decoded video and audio, with transferred media hashes matching the source receipts. Each clip contained forty-nine frames at twenty-four frames per second, at a modest test resolution. Observed baseline-to-terminal intervals were roughly half a minute. Resource samples showed nearly exhausted device memory and limited remaining system memory. Those samples qualified only the tested starter profile; they did not establish maximum duration, resolution, exact peaks or subjective output quality.

Generation intent, accepted identity, terminal history and media proof remained separate. The test held cooperative ownership throughout execution. Source review checked that uncertain outcomes retain ownership and are inspected without replay. Source review required that ownership also survive uncertain asynchronous release. Global unload was permitted only from a clean initial model inventory, uninterrupted owned operation sequence and terminal completion. After each run, exact owned release and actual zero cached models were verified. Ordinary interface admission does not inherit the test runner's full-duration ownership, and unrelated programs can ignore cooperative coordination.

The resulting engineering lesson is to verify the complete native workflow, account for both host and device memory, and distinguish successful execution from safe release. Larger clips, enhanced second-pass output, broad quality comparisons, physical-device and reboot behavior, and injected acknowledgement-loss tests were outside this evidence. The record is retrospective and contains no deployable workflow, private media, current topology or operational commands.
