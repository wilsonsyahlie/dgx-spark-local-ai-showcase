# What a local model trial actually proved

A model experiment produced a better coding result while exposing separate engineering and workflow failures. Keeping those outcomes separate made the evaluation useful.

The preparation stage first ran short of disk reserve during image import. After explicitly approved cleanup, retained build work completed successfully. A later stop exposed a policy-phase mistake: a preparation limit had been applied during inference startup. Correcting the boundary retained the original resource protections and accumulated reference.

The next lesson concerned streaming. An end-of-message event arrived before final HTTP settlement. A test closed too early and immediately checked idle, confusing a checker race with model failure. The corrected test consumed the response fully and required durable completion. Cancellation followed an exact ownership record and native handler evidence rather than assuming a public response identifier was the ownership key.

One fresh Python task passed 15 independent checks, compared with 14 for the earlier candidate, and finished in about 148 rather than 210 seconds. That supports a useful improvement on that task. It does not establish universal superiority.

The creative task crossed its requested output-directory boundary. Its partial result was preserved, the task was stopped, and an explicit correction began an assisted attempt. A corrected attempt cannot silently stand in for the first result.

The assisted attempt reached its deadline while fixing its own mocked graphics test. An operator then published the already generated file for inspection. This was not successful autonomous completion or publication.

The actual page rendered in desktop and phone-width browser checks, with working animation, pause, camera controls, reset and refresh. Local vision compared actual reference and output images and judged the scene partially successful: the main subject was recognizable, but lighting and scenery remained basic. Neither still images nor generic control tests establish physically correct cycling or seamless scenery motion.

The owner chose the previously working model rather than promoting the candidate. The practical lesson was to weigh complete task behavior alongside a better coding score. This retrospective contains no deployment recipe, current service layout, private artifacts or operational commands.

Restoration checks separately confirmed the retained model loaded and a fresh assistant conversation returned the expected answer. That first cold reply took roughly two minutes. The resource interface correctly reported the running state and controls, but its memory attribution still showed zero; that display check failed and was recorded without an unrelated dashboard change. Broader stability remains unqualified.
