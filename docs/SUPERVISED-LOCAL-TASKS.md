# Supervision needs exercised tools and explicit ownership

A supervised task experiment combined an owner-authorized cloud coordinator
with local workers. The goal was one request followed by planning, delegation,
inspection and takeover when local work was insufficient. Both roles could
write their task files under standing authorization, with automatic backups.
This was a scoped exception for submitted task content; it did not introduce
a general cloud fallback or import private knowledge into the coordinator.

The first important failure was the difference between declared and working
tools. Protocol capture initially read the wrong declaration field. Later,
real model turns found a disabled executor and a missing companion executable.
No output was falsely accepted. Correcting the restricted tool runtime and
qualifying its exact fingerprints produced real file operations.

Lifecycle review mattered just as much as reasoning. A delayed action could
target a newer task generation, a lost acknowledgement could create duplicate
work, and restart could confuse retained artifacts with settled execution.
Expected generations, stable submission identities and exact owned request,
executor and process receipts corrected those cases. An unidentified possibly
dispatched request remained fenced rather than being inferred safe from idle.

Failed tests also exposed process mistakes. A fault fixture changed shared
timing used by cleanup; another injected before launch. An idle activation
briefly proceeded after a failed check was logged without asserting its status.
It was contained before task execution, and later gates required positive
results. Those failed attempts remained part of the engineering record.

Actual local drafting produced files that the supervisor independently read
and checked. A deliberately faulty draft failed a real assertion; the
supervisor then repaired it and passed checks bound to the final file hashes.
An active local request stopped with an exact abort receipt, and a question
survived restart before completing in the same context. Thirty-seven focused
test executions and browser exercises covered these lifecycle boundaries,
stale reads, retry, duplicates and a phone-sized view.

The presentation boundary received its own correction. A nominally protected
preview was blank despite header checks. The final view displayed escaped
file text and verified that script and redirect content stayed inert.

These are bounded engineering demonstrations. They do not establish arbitrary
model correctness, physical device acceptance, long endurance or best-model
selection. The lesson is to prove actual tool effects, preserve ownership and
failures, and keep result inspection independent of a worker's claims.

The final backup audit also exposed a preservation mistake: two snapshots with
the same filename shared one destination. A non-inference capture snapshot was
reconstructed from its retained pure builder and matched its independently
recorded original hash exactly. The failed copy history remained explicit; no
production state was restored. Unique destinations, a real collision fixture
and a complete indexed hash scan qualified the repair. Backup creation and
continued byte preservation required separate evidence.
