# Making reasoning intent visible

The owner wanted to see and choose reasoning effort in a conversation. The earlier
interface showed work in progress but hid a fixed default. The experiment added
five choices and a separate label for the current turn. The next preference was
not treated as evidence about a message that had already been sent.

## A dropdown is only the first layer

The setting was captured with the original action identity before transmission.
An uncertain acknowledgement retained that exact choice through refresh and retry.
New turns recorded their settings atomically; later changes could not alter an
older turn. A saved setting and an accepted runtime request were displayed as
different states, with persisted context checked separately during qualification.

Protocol capture mattered. An advertised delegation mode emitted a different
reasoning effort. It was excluded rather than presented as an exact setting or
used as a reason to broaden the system's capabilities. The qualified choices
retained the previously bounded tool surface.

## Keep failures as evidence

Independent reviews found two migration failures: partial state loss and paired
state loss could make a new non-default turn look like legacy default behavior.
A durable migration marker and contradictory newer receipts prevented rebootstrap;
missing new settings rejected instead of silently changing intent. The exact
regressions were retained before activation.

One qualification fixture also revealed that changing a module variable does not
change a constructor default already bound to the original store. The fixture was
closed only after a consistent backup, matching owned-process settlement and proof
that no model turn or task file write occurred. Its history remained. Explicit
fixture isolation corrected the test harness without an unrelated store refactor.

## What the experiment established

Request/state tests and browser cases covered every choice, duplicate and stale
actions, errors, uncertain acknowledgements, cached-page return and narrow layouts.
Two actual selected turns stayed in the same conversation and matched persisted
reasoning context. Exact current-output checks and automatic replacement backups
passed. Restart recovery preserved the setting and unsent draft through reads,
without replaying work. Existing project state remained identical.

The result established visible, traceable intent and recovery for the checked
paths. It did not establish that higher effort was always better, compare quality
or latency, qualify every level with real model tasks, prove a physical device,
or establish prolonged stability and rollback execution. This account is a
retrospective engineering story, not a deployable configuration.

### A selected setting did not guarantee a successful first attempt

One real worker exhausted its budget, left a content mismatch and attempted a
write through a checker whose workspace was read-only. The rejected check stayed
in the record. The supervisor inspected the result, used its authorized file
tool and verified the corrected current artifact. Hashing desired bytes alone
was not accepted as proof of the file. Recovery preserved the boundary; it did
not justify a stronger claim about reasoning quality.
