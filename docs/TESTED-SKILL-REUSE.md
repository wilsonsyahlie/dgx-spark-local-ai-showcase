# Reusable controllers need a transfer test

Coached progress and saved instructions did not establish reliable reuse. Five
bounded paired comparisons tested reusable code packages against the same local
worker without those packages. Each comparison used ten task pairs, each with two fresh workspaces,
equal model/tool budgets, balanced order, frozen acceptance rules and zero corrective
coaching. Supervisor code authorship remained distinct from local application writes.

The first package supplied storage, latest-request and audio primitives. Its ten
variants shared one parameterized contract. It was preserved and rejected before a
second candidate began. The second supplied a complete UI/recovery controller;
workers authored quantity, duplicate, ordering, summary and catalog adapters. Fresh
contracts exercised actual behavioral differences rather than names alone. This
measures the supplied controller's practical value, including reduced reconstruction
work; it does not isolate instruction-only skill improvement.

Actual output inspection found one adapter accepting a top-level list when a nested
envelope was required. Seven conservative checks of that existing explicit contract
were qualified and run on both arms without changing frozen scores or giving worker
feedback. Original second-round rubric scores were 0/10 baseline and 9/10 package;
strict completion counts are in the table. This supplemental audit was added after
inspection, so it is not a preregistered independent experiment.

One minimal correction moved required envelope/list/item validation into the supplied
controller before the local mapping callback. The third round used new behavioral
combinations and froze these shape checks before inference. It is explicitly informed
by the earlier failures; task family, worker route and budgets stayed fixed. No earlier
worker call was retried; original artifacts remained unchanged. An earlier internal stopping rule was explicitly superseded after the newly measured integration defects, within the original library scope; retained results prevent that revision from hiding failed approaches.

The shape-guard round was rejected: incomplete configuration copies, synchronous
head-script mounting and an incorrect API argument count prevented integration.
A fourth minimal library correction owns page readiness and bounded loading of the
sealed task configuration, with one primary factory interface and only observed
legacy handoffs. The canonical configuration is authoritative; five local business
callbacks remain required and independently hardcoded errors remain visible.
Changing only the controller in exact copies of six failed applications produced
full passes. Separate startup qualification covers configuration failure, timeout,
retry, ignored aborts, duplicate mounting, invalid adapters/factories and recovery.
The common comparison rubric remains unchanged; fresh contracts are frozen before
new inference. That startup round completed8/10 assisted apps but was rejected: two
apps requested root assets supplied only under the nested package path. A fifth
packaging correction exposes exactly two documented, sealed byte-identical root
copies and one exact HTML example. Both unchanged failed applications pass only
with that delivery interface. A narrowly changed recorder accepts both documented
controller paths and binds canonical response bytes; all34 behavior assertions
remain equivalent. Wrong bytes and unsupported paths fail reuse evidence even
when behavior passes. Runtime qualification is inherited only by exact unchanged
source/dependency equivalence; delivery has fresh separate tests. All rounds are retained. These corrections were informed by failures,
so this is operational qualification rather than an unbiased candidate search.

No successful fresh-reuse acceptance is claimed; the conservative acceptance gate was not fully met.

The comparisons use different contracts, so their absolute scores are not a direct
head-to-head candidate ranking. Gains are measured within each paired comparison.
No uncertainty or unfinished executor/browser work was scored as successful. A
missing app's quiet-page checks do not constitute useful task completion. Underlying
causes of generic incomplete model responses remain unproven because the worker did
not retain distinguishing terminal details. An independently reviewed read-only lookup of one retained failed response found no stored terminal object. Its diagnostic bookkeeping settled separately from the original inference. Narrow existing-log checks did not establish the cause; an unavailable log source is explicitly limited. These observations do not retrospectively assign a common cause to earlier failures. Better worker failure reporting is a separately scoped follow-up, not a silent package change.

## The evaluator needed testing too

Independent review caught audio API bias, mutations lost after reload, deliberately
held routes without explicit teardown, stale file bindings and lifecycle labels
confusing settlement with success. Later review strengthened min-anchored quantities,
complete mixed-array validation and matching any complete early instruction read.
Controller state is staged before committing; injected ordering/summary failures
preserved the screen and subsequent saved state and then recovered.

A separate correct interface using separators, units and a labeled total initially
failed an overly exact text assertion. Before inference, the grader changed to
independent semantic row/order/quantity checks. Decorated positives passed; wrong
amounts/order, extra numbers and substring labels failed. Correct and targeted
broken controls qualified the final checker before the frozen comparison.

One regenerated preliminary unit receipt lacked a dedicated prior copy. The original
bytes were later reconstructed and matched to their recorded cryptographic hash.
This does not establish that a backup existed before replacement. Fresh matching
behavioral evidence supported qualification; later receipt creation is immutable.
The historical pre-backup violation remains explicit. Raw teacher practice reports
did not serialize artifact manifests. Current leaves match the original frozen
generator; this is no invented historical leaf receipt. A preparation helper that
assumed worker-report fields failed before writing a receipt. Independent review
also required exact qualified delivery file-set/hash matching before final freeze;
no corruption was observed.

An early startup harness cleaned up after closing its browser transport and did not
retain browser identities. The failed run is retained; missing historical identities
are not reconstructed. Later exact closure evidence is separate. Cleanup controls
now preserve original and teardown errors, close owned resources and reject a test
body that passed while cleanup failed.

## Boundaries

This is external package assistance within one browser-app family, not changed
weights, intrinsic model learning, broad autonomous reliability or automatic
conversational-agent skill discovery. Browser checks used controlled catalog
responses and real synthesized audio measurements; physical hearing and a real
production catalog integration remain untested. Worker-time medians include partial
and failed baseline jobs, so they are not time-to-success claims.

Retained failure reports, immutable source/artifact hashes, exact owned-work closure,
backups and independent review support the stated decision. Existing production
configuration and stopped projects were outside the change. This retrospective
contains no deployable configuration or operational artifacts.
