# A finished transfer can still be an unfinished request

An episodic media recovery exposed several independent holds. A pack used a different numbering scheme, subtitle metadata failed the existing dialogue rule, and successful-grab history prevented ordinary replacements even though the library files were absent.

A decoder failure needed a separate experiment. Keeping the file, streams and execution environment fixed, random-seek samples emitted a specific reference error while sequential decoding to the same windows passed strict checks. The resulting verifier retries only that narrow, bounded case. It preserves the original failure and still requires clean decoding, complete packet coverage, native-language speech, English dialogue and matching media bytes within the original deadline.

Qualification included a full real-file proof, clean samples from other codec families and rejection of truncated inputs. The latter is limited evidence, not a claim to detect every kind of corruption. Reviews and actual-file drift tests preceded staged activation with preserved ownership, backups, pointer-last publication and consumed-action protection. A fresh process and a natural scheduled execution confirmed the deployed policy.

Separately, positive episode identities repaired the numbering issue. A supported failure acknowledgement released the native replacement search without deleting the retained source or changing the verified installed copy. Actual replacement transfers followed.

The narrow verifier repair was deployed; remaining pack imports and human playback were still open at this checkpoint. Transfer, qualification, import and availability need their own evidence. The response kept existing ownership and content checks rather than adding another recurring repair loop.
