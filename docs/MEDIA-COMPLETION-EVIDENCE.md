# A completion flag is a claim that needs evidence

A media file can advertise its full duration while its playable data stops early. A successful decoder exit can coexist with a diagnostic about premature termination. Those observations changed the validation boundary: completion needs evidence from the body, not just the header or process result.

The engineering work separated request identity, source integrity, mutation authority, installed content and selected playback tracks. Bounded local checks inspect packet timelines and decoding, compare complete-file hashes and verify actual language evidence. Required subtitles are checked from text or subtitle-only raster output so background text cannot supply a false result.

Recovery also distinguishes expired history from failed work. If an old command record disappears, exact current physical evidence may establish what exists now. It does not prove the missing historical acknowledgment, and it never grants permission to repeat an uncertain action.

The selected audio and caption tracks must be the ones that were validated. This closes a subtle gap where a file contains a correct track but the player retains a different, mislabeled one. Historical receipt compatibility remains explicit and cannot bypass reservations for uncertain writes.

Natural scheduled runs verified the deployed ingestion checks and an already correct selection without another mutation. Tests also preserved failures involving wrong language, damaged bytes, changed ownership or targets, interrupted acknowledgments and accumulated job history. Request-validation checks were adopted separately: real route/database tests and authenticated live rejection checks demonstrated that unsupported scope and stale edits do not become saved requests. Existing request monitoring resumed naturally with prior authority preserved.

The result is bounded evidence, not a universal media guarantee. Sampled language checks do not certify translation or perfect synchronization, and a title without an available source is not described as downloaded. This retrospective provides no deployment instructions, configuration, access details or private media artifacts.

A maintenance guard also refused a late restart window before dispatch. The exact failure was retained and joined to source ordering; the consumed attempt was not reset. A separately reviewed attempt preserved private state and repeated identity checks after long-running backup phases. The operational evidence comes from process closure, database consistency and state comparisons, without claiming that a termination signal proves graceful application flushing.


### 2026-10-26 — Correcting identity before replacing a video

A movie appeared to offer only a trailer because a same-title catalogue lookup associated it with an unrelated short. The existing full-length media did not need replacement. One scoped metadata correction preserved the media and viewing state, and the owner confirmed full-movie playback.

Verification separated three questions: does the catalogue identify the intended work, is the existing media readable, and can the viewer play it? Sampled decoding and near-end packet checks supported readability without claiming exhaustive decoding. An optional content check timed out and was retained as unqualified evidence. The catalogue updated asynchronously; repeated observation confirmed the result without replaying the write. This is a retrospective lesson about evidence boundaries, not a global matching policy or a guarantee against every playback issue.
